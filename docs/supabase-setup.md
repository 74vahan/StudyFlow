# Подключение Supabase (День 6–8)

Пока ключи Supabase не заданы, приложение работает на локальном хранилище (localStorage). Как только выполнишь шаги ниже — оно автоматически переключится на реальную базу Postgres с авторизацией и защитой RLS (изоляция данных между пользователями — AC-04).

## Шаг 1. Создать проект
1. Зайди на https://supabase.com и войди (можно через GitHub).
2. **New project** → задай имя (например `studyflow`), пароль базы (сохрани его), регион поближе.
3. Подожди ~1–2 минуты, пока проект создастся.

## Шаг 2. Взять ключи
Dashboard проекта → **Project Settings → API**:
- **Project URL** → это `NEXT_PUBLIC_SUPABASE_URL`
- **anon public** ключ (раздел API Keys) → это `NEXT_PUBLIC_SUPABASE_ANON_KEY`

> Бери именно **anon/publishable** ключ. `service_role` — секретный, его в приложение не вставляем.

## Шаг 3. Создать файл .env.local
В корне проекта скопируй `.env.example` в `.env.local` и впиши свои значения:
```
NEXT_PUBLIC_SUPABASE_URL=https://твой-проект.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=твой-anon-ключ
```
`.env.local` в git не попадает (он в `.gitignore`).

## Шаг 4. Создать таблицу и RLS
Dashboard → **SQL Editor → New query** → вставь целиком содержимое файла
[`supabase/schema.sql`](../supabase/schema.sql) → **Run**.

Это создаёт таблицу `tasks`, включает Row Level Security и политики «только свои строки».

## Шаг 5. Упростить вход для демо (по желанию, но удобно)
Dashboard → **Authentication → Sign In / Providers → Email** → выключи **Confirm email**.
Тогда регистрация сразу выполняет вход (без письма-подтверждения). Для экзамена это нормально; при желании можно оставить подтверждение включённым.

## Шаг 6. Перезапустить приложение
```bash
npm run dev
```
Открой http://localhost:3000, зарегистрируйся — теперь данные лежат в Supabase.

## Как проверить изоляцию данных (AC-04)
1. Зарегистрируйся как пользователь A, создай пару задач.
2. Выйди, зарегистрируйся как пользователь B — список задач пустой.
3. Задачи A и B не видят друг друга. Это обеспечивают RLS-политики, а не только UI.

## Деплой (День 13)
Те же две переменные (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`) нужно задать в настройках Vercel (Production). SQL из шага 4 выполняется один раз на проекте Supabase.

# StudyFlow — Документ требований

> Учебная платформа управления задачами для студентов.
> Экзаменационный проект Vibe Coding. Стек: Next.js (App Router, TS) + Supabase (Auth + Postgres + RLS) + Claude API + Vercel.

## 1. Целевой пользователь
Студент, которому нужно организовать учёбу: вести список учебных задач, следить за дедлайнами и приоритетами, видеть прогресс. Работает и с телефона, и с компьютера.

## 2. Проблема
Задачи разбросаны по заметкам, мессенджерам и голове. Нет единого места, где видно, что просрочено, что в работе и что готово. Непонятно, с чего начать большую задачу.

## 3. MVP (обязательное)
| Модуль | Что должно работать |
|---|---|
| Аккаунт | Регистрация и вход. Вошедший видит только свои данные. |
| Задачи (CRUD) | Создать, посмотреть, изменить, удалить задачу. |
| Поля задачи | Заголовок, описание (необяз.), дедлайн, приоритет, статус. |
| Поиск и фильтры | Поиск по заголовку; фильтр по статусу и приоритету. |
| Dashboard | Счётчики: всего / выполнено / в процессе. |
| AI-функция | Из описания задачи — план мелких шагов (Claude API). |
| Responsive | Основные экраны удобны на телефоне и ПК. |

## 4. Границы (Scope)
**В MVP входит:** всё из таблицы выше, безопасный вход, сохраняемые данные, AI, тесты, деплой.
**НЕ входит (bonus, только после MVP):** календарь, напоминания, тёмная тема, внешние API, красивые графики статистики.

## 5. Модель данных
**auth.users** — управляется Supabase Auth (id, email, …).

**public.tasks**
| Поле | Тип | Примечание |
|---|---|---|
| id | uuid (PK) | default gen_random_uuid() |
| user_id | uuid (FK → auth.users.id) | владелец задачи |
| title | text NOT NULL | заголовок |
| description | text NULL | описание |
| due_date | date NULL | дедлайн |
| priority | text | 'low' \| 'medium' \| 'high' |
| status | text | 'todo' \| 'in_progress' \| 'done' |
| created_at | timestamptz | default now() |
| updated_at | timestamptz | default now() |

**Безопасность:** на таблице `tasks` включён RLS. Политики: пользователь может читать/изменять/удалять только строки, где `user_id = auth.uid()`. Это ключ к AC-04 (изоляция данных).

## 6. Страницы (маршруты)
| Маршрут | Назначение |
|---|---|
| `/` | Лендинг / редирект на /dashboard (если вошёл) или /login |
| `/login` | Вход |
| `/register` | Регистрация |
| `/dashboard` | Счётчики + последние задачи |
| `/tasks` | Список задач: поиск, фильтры, CRUD |
| `/tasks/new` | Создание задачи (+ кнопка AI-план) |
| `/tasks/[id]` | Просмотр/редактирование задачи |
| `/api/ai/plan` | Серверный роут → Claude API |

## 7. Acceptance Criteria (чек-лист сдачи)
| ID | Сценарий | Успешный результат |
|---|---|---|
| AC-01 | Регистрация и вход | При неверных данных — понятная ошибка; при верных — вход. |
| AC-02 | Создать задачу | Задача с валидным заголовком сохраняется и появляется в списке. |
| AC-03 | Изменить / удалить | Изменение сохраняется; после удаления задача исчезает. |
| AC-04 | Изоляция данных | Один пользователь не видит и не меняет задачи другого. |
| AC-05 | Поиск / фильтр | Результаты меняются по тексту поиска и выбранному фильтру. |
| AC-06 | Dashboard | Числа совпадают с реальным количеством задач. |
| AC-07 | AI-помощник | На пустой/непонятный ввод — безопасное понятное сообщение. |
| AC-08 | Обновление страницы | Сохранённые данные не исчезают после refresh. |
| AC-09 | Маленький экран | Основные действия доступны с телефона без горизонтальной прокрутки. |
| AC-10 | Прод-версия | Деплой-ссылка открывается, основной поток работает. |

## 8. Разбивка на мелкие задачи (для работы с Claude)
1. Скелет Next.js + Tailwind + i18n (en/ru/hy) — ✅ День 1–2.
2. Макеты страниц (login, tasks, dashboard) со статикой.
3. CRUD задач на локальном состоянии/моках + состояния loading/empty/error.
4. Supabase: проект, таблица tasks, RLS-политики.
5. Supabase Auth: регистрация/вход, защита маршрутов.
6. Подключить CRUD к Supabase (реальные данные).
7. Поиск + фильтры + dashboard-счётчики.
8. AI-роут → Claude API + обработка ошибок/пустого ввода.
9. Тесты (≥8 сценариев), security-review, responsive.
10. Деплой на Vercel, env-переменные, README, доказательства.

## 9. Риски и как с ними работаем
- **Изоляция данных (AC-04)** — главный риск оценки. Проверяем RLS двумя аккаунтами.
- **Секреты** — `ANTHROPIC_API_KEY` и ключи Supabase только в `.env` (в `.gitignore`), в репо — `.env.example`.
- **AI** — обрабатываем пустой ввод, ошибку/таймаут API; ключ только на сервере.
- **Авторизация на сервере** — проверка прав в API/RLS, а не только в UI.

# 06 — Безопасность

## Секреты (правило VibeCode #9)
- Нет токенов/паролей/ключей в коде и git. Только `.env.local` (в `.gitignore`); в репо — `.env.example`.
- `DATABASE_URL`, `AUTH_SECRET`, `TEACHER_PIN_HASH_B64`, `ANTHROPIC_API_KEY` — только сервер, не `NEXT_PUBLIC_`.
- Пароли учеников — только bcrypt-хеш. PIN учителя — только bcrypt-хеш (хранится base64, чтобы `$` не ломался при .env-раскрытии).

## Роли и вход
- Ученик: email+пароль (bcrypt), сессия — JWT (HS256, `jose`) в HTTP-only cookie (`sameSite=lax`, `secure` в проде).
- Учитель: 6-значный PIN → bcrypt.compare. Защита перебора: in-memory rate-limit + блокировка после 5 ошибок на 5 мин (`lib/auth/rate-limit.ts`). ⚠️ in-memory = на один инстанс; для мульти-инстанса нужен общий стор (Redis).
- Логин/регистрация не различают «нет email»/«неверный пароль» наружу.

## Авторизация и изоляция данных (AC-04)
- Всё на сервере: роль из сессии (не из запроса).
- Ученик: запросы задач всегда `WHERE assignee_id = session.userId`; может менять только `status` своей задачи; POST/DELETE задач и управление классом — 403.
- Членство в классе = строка `class_members`; не-член отбрасывается на `/pending` (AppShell) и получает пустые данные; FK `tasks.assignee_id → class_members` не даёт выдать задачу не-члену.
- Роутинг по роли — `src/proxy.ts` (Edge, проверка JWT); API сами отдают 401/403.
- Проверять изоляцию двумя аккаунтами.

## Ввод и ошибки
- Валидация форм и API (`validation.ts`, `tasks/validate.ts`); ошибки без утечек.
- AI-роут: безопасная обработка пустого ввода и сбоя API (AC-07).

## Чек-лист безопасности (День 11–12)
- [ ] Секреты не в коде/git. [ ] API проверяют роль/сессию (401/403).
- [ ] Ученик видит только свои задачи (проверено 2 аккаунтами). [ ] PIN и пароли — только хеши.
- [ ] PIN защищён от перебора (rate-limit). [ ] Ввод валидируется, ошибки без утечек.
- [ ] README/доки без реальных секретов.

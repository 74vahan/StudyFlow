# 06 — Безопасность

## Секреты (правило VibeCode #9)
- Нет токенов/паролей/ключей в коде и git.
- Секреты только в `.env.local` (в `.gitignore`); в репо — `.env.example` с пустыми значениями.
- `NEXT_PUBLIC_*` уходит в браузер — туда только публичные ключи.
- `service_role` и `ANTHROPIC_API_KEY` — никогда не `NEXT_PUBLIC_`.

## Авторизация и изоляция данных (AC-04)
- Проверка прав на сервере (RLS + Supabase Auth), не только в UI.
- Каждый пользователь работает только со своими задачами: `auth.uid() = tasks.user_id`.
- UPDATE-политики с `USING` и `WITH CHECK` (иначе можно сменить владельца).
- Проверять изоляцию двумя реальными аккаунтами.

## Ввод и ошибки
- Валидировать вход форм и API; ошибки не раскрывают секретных деталей.
- AI-роут: обрабатывать пустой/непонятный ввод и сбой API безопасно (AC-07).

## Чек-лист безопасности (заполнять в День 11–12)
- [ ] Ключи/секреты не в коде и не в git.
- [ ] API проверяют права на сервере.
- [ ] Пользователь видит только свои данные (проверено 2 аккаунтами).
- [ ] Ввод валидируется, ошибки без утечек.
- [ ] Нет слепо принятых опасных изменений от Claude.
- [ ] README объясняет env без реальных значений.

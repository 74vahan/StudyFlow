# StudyFlow — Документ требований

> Классная платформа задач: **учитель** раздаёт задачи **ученикам**, каждый видит только свои.
> Экзаменационный проект Vibe Coding. Стек: Next.js (App Router, TS) + MySQL (через mysql2) + своя серверная авторизация (учитель — PIN; ученик — email/пароль; JWT в cookie) + Claude API + Vercel.

## 1. Целевые пользователи
- **Учитель** (один): раздаёт задачи ученикам, управляет составом класса. Вход по 6-значному PIN.
- **Ученик**: регистрируется (email/пароль), видит и выполняет только выданные ему задачи.

## 2. Проблема
Учителю негде удобно раздавать индивидуальные задачи и видеть прогресс каждого ученика, а ученику — иметь одно место со своими задачами, дедлайнами и статусами.

## 3. MVP (обязательное)
| Модуль | Что должно работать |
|---|---|
| Роли и вход | Ученик: регистрация/вход (email+пароль). Учитель: вход по 6-значному PIN. |
| Класс | Ученик после регистрации — «не в классе» (экран /pending), пока учитель не добавит его. |
| Задачи | Учитель создаёт/редактирует/удаляет и назначает задачу конкретному ученику. |
| Ученик и задача | Видит только свои задачи, меняет только статус (todo/в работе/готово). |
| Изоляция | Ученик не видит и не меняет задачи другого. |
| Поля задачи | Заголовок, описание (необяз.), дедлайн, приоритет, статус. |
| Поиск и фильтры | Поиск по заголовку; фильтр по статусу и приоритету. |
| Dashboard | Счётчики ученика: всего / выполнено / в процессе. |
| AI-функция | Из описания задачи — план мелких шагов (Claude API). |
| Responsive | Основные экраны удобны на телефоне и ПК. |

## 4. Границы (Scope)
**В MVP входит:** всё из таблицы выше, безопасный вход, сохраняемые данные, AI, тесты, деплой.
**НЕ входит (bonus, только после MVP):** календарь, напоминания, тёмная тема, внешние API, красивые графики статистики.

## 5. Модель данных (MySQL, см. `../../StudyFlow_infra/db/schema.sql`)
**users** — ученики (учитель — не запись в БД, вход по PIN).
| Поле | Тип | Примечание |
|---|---|---|
| id | CHAR(36) (PK) | UUID |
| email | VARCHAR(255) UNIQUE | логин ученика |
| password_hash | VARCHAR(255) | bcrypt-хеш |
| created_at | TIMESTAMP | default CURRENT_TIMESTAMP |

**class_members** — единственный класс; членство = наличие строки.
| Поле | Тип | Примечание |
|---|---|---|
| user_id | CHAR(36) (PK, FK → users.id, CASCADE) | ученик в классе |
| joined_at | TIMESTAMP | когда добавлен |

**tasks**
| Поле | Тип | Примечание |
|---|---|---|
| id | CHAR(36) (PK) | UUID |
| assignee_id | CHAR(36) (FK → class_members.user_id, CASCADE) | кому выдана |
| title | VARCHAR(255) NOT NULL | заголовок |
| description | TEXT NULL | описание |
| due_date | DATE NULL | дедлайн |
| priority | ENUM('low','medium','high') | приоритет |
| status | ENUM('todo','in_progress','done') | статус |
| created_at / updated_at | TIMESTAMP | updated_at ON UPDATE |

**Безопасность:** у MySQL нет RLS, поэтому изоляция (AC-04) — **на сервере**: роль берётся из cookie-сессии, запросы ученика фильтруются по `assignee_id = session.userId` (`src/lib/tasks/mysql-store.ts`, `src/app/api/tasks/*`); ученик меняет только `status`. Клиент `assignee_id` не передаёт. FK гарантирует, что задача выдана только члену класса. PIN учителя — bcrypt-хеш + rate-limit.

## 6. Страницы (маршруты)
| Маршрут | Роль | Назначение |
|---|---|---|
| `/` | — | Лендинг, редирект по роли; ссылка «вход учителя» |
| `/login`, `/register` | ученик | Вход / регистрация |
| `/teacher/login` | учитель | Вход по 6-значному PIN |
| `/teacher` | учитель | Ученики (добавить/убрать из класса) + выдача/список задач |
| `/pending` | ученик без класса | Экран «ты ещё не в классе» (стилизованный 404) |
| `/dashboard` | ученик | Счётчики + последние свои задачи |
| `/tasks`, `/tasks/[id]` | ученик | Свои задачи: поиск, фильтры, смена статуса |
| `/api/ai/plan` | — | Серверный роут → Claude API (День 9–10) |

## 7. Acceptance Criteria (чек-лист сдачи)
| ID | Сценарий | Успешный результат |
|---|---|---|
| AC-01 | Регистрация и вход | При неверных данных — понятная ошибка; при верных — вход. |
| AC-02 | Создать задачу | Задача с валидным заголовком сохраняется и появляется в списке. |
| AC-03 | Изменить / удалить | Изменение сохраняется; после удаления задача исчезает. |
| AC-04 | Изоляция данных | Один пользователь не видит и не меняет задачи другого. |
| AC-05 | Поиск / фильтр | Результаты меняются по тексту поиска и выбранному фильтру. |
| AC-06 | Dashboard | Числа совпадают с реальным количеством задач. |
| AC-07 | AI-помощник | На пустой/непонятный ввод — безопасное понятное сообщение. |
| AC-08 | Обновление страницы | Сохранённые данные не исчезают после refresh. |
| AC-09 | Маленький экран | Основные действия доступны с телефона без горизонтальной прокрутки. |
| AC-10 | Прод-версия | Деплой-ссылка открывается, основной поток работает. |

## 8. Разбивка на мелкие задачи (для работы с Claude)
1. Скелет Next.js + Tailwind + i18n (en/ru/hy) — ✅ День 1–2.
2. Макеты страниц (login, tasks, dashboard) со статикой.
3. CRUD задач на локальном состоянии/моках + состояния loading/empty/error.
4. MySQL: база + таблицы `users`/`tasks` (`db/schema.sql`), пул соединений.
5. Своя серверная авторизация: регистрация/вход (bcrypt + JWT-cookie), защита маршрутов (proxy).
6. Подключить CRUD к MySQL через серверные API-роуты (реальные данные).
7. Поиск + фильтры + dashboard-счётчики.
8. AI-роут → Claude API + обработка ошибок/пустого ввода.
9. Тесты (≥8 сценариев), security-review, responsive.
10. Деплой на Vercel, env-переменные, README, доказательства.

## 9. Риски и как с ними работаем
- **Изоляция данных (AC-04)** — главный риск оценки. Проверяем двумя аккаунтами: запросы задач на сервере фильтруются по `user_id` из сессии.
- **Секреты** — `DATABASE_URL`, `AUTH_SECRET`, `ANTHROPIC_API_KEY` только в `.env.local` (в `.gitignore`), в репо — `.env.example`.
- **AI** — обрабатываем пустой ввод, ошибку/таймаут API; ключ только на сервере.
- **Авторизация на сервере** — проверка прав в API-роутах (сессия + `WHERE user_id = ?`), а не только в UI.
